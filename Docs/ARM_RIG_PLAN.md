## 왜 하는가

지금은 공격 동작이 Attack 시트 6장에 검과 함께 그려져 있다. 그래서 무기마다 동작을 바꿀 수 없고,
`PlayerWeaponVisual`이 그리는 무기(AXE)와 그림 속 검이 동시에 보인다.
사용자는 무기군을 구현하려면 **팔을 분리해서 베기·찌르기·내려찍기 같은 동작을 넣어야 한다**고 판단했다.

## 사용자 결정 (2026-10-05)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 팔 수 | **양팔 모두 분리** |
| 2 | 팔 마디 | **두 마디** (윗팔 / 아랫팔+손) |
| 3 | 회전 방식 | **실시간 회전** (게임이 매 프레임 무기·팔 그림을 각도대로 돌린다. 중간 각도에서 픽셀이 계단지는 것은 감수) |
| 4 | 조준 | **몸통 4방향 + 팔·무기 360°**로 진행한다. **언제든 다른 방식으로 바꿀 수 있게 열어 둔다** |
| 5 | Death·Skill | **기존 시트를 재생**하고, 그 시트에서 **무기만 지운다** |
| 6 | 무기별 동작 | **무기를 하나씩 구현하며, 그때마다 사용자와 따로 이야기해서 정한다** (아래 "무기 구현 방식") |

## 목표 구조

```
E 몸통 (팔·무기 없는 시트, 4방향)   ← 대기·걷기 오르내림, 공격 시 전진·기울기
 ├ 어깨 ─ 윗팔 ─ 팔꿈치 ─ 아랫팔+손   ← 실시간 회전
 │                         └ 무기 (손잡이를 손에 고정)
 └ 반대쪽 어깨 ─ 윗팔 ─ 아랫팔+손
```

## 단계 (모델 제안 — 진행하면서 조정)

### 1. 아트 분리 (`Tools/build_e_character_b.py`)
- Idle 4방향에서 **양팔과 검을 지운 몸통**을 만든다. 팔이 가리던 망토·몸통 자리는 주변 색으로 메운다.
- 지운 팔에서 **윗팔**, **아랫팔+손** 조각을 방향별로 잘라 낸다. **어깨·팔꿈치·손잡이 위치**를 방향별 데이터로 저장한다.
- Walk는 이미 "Idle 상체 + 다리"로 만들고 있으므로 자동으로 팔 없는 버전이 된다.
- Death·Skill 시트에서 무기(검)만 지운다 (결정 5).
- ⚠ 위험: 정면에서는 팔이 망토 앞에 있어 지운 자리를 메운 결과가 어색할 수 있다. 자동으로 부족하면 그 부분만 손보거나 다시 생성한다.

### 2. 모션 로직 (순수 C#, EditMode TDD)
- 기존 `WeaponArmMotion`/`ArmPose`를 확장한다: 어깨 각도, 팔꿈치 각도, 무기 각도, 몸 기울기.
- 타이밍은 기존 `AttackMotionDef`(예비·타격·회수)를 그대로 써서 **판정·이펙트·팔이 같은 시계**로 움직인다.
- 처음에는 동작 종류를 하나(기본 베기)만 만든다. 나머지는 무기를 구현할 때 하나씩 추가한다 (결정 6).

### 3. 런타임 리그
- `PlayerWeaponVisual`과 `PlayerArms`를 `ECharacterRig` 하나로 합친다.
- 방향에 따라 그리는 순서를 바꾼다 (정면: 무기 팔이 몸 앞 / 뒷모습: 몸 뒤 / 옆모습: 가까운 팔이 앞).
- 걷기에서는 팔을 걸음과 반대로 흔든다 (`WALK_STEPS`와 같은 프레임).
- 공격 중 몸통은 Attack 시트 대신 Idle 몸통 + 전진·기울기를 쓰고, 동작은 팔이 맡는다.
- **조준 방식 교체 지점**(결정 4): 팔·무기가 쓰는 조준각을 한 곳(`PlayerController.AimDirection` → 리그 입력)에서
  받도록 한다. 4방향·8방향으로 바꾸려면 이미 있는 `AimGeometry.Snap(dir, steps)`의 단계 수만 바꾸면 된다.

### 4. 무기 구현 (무기 하나씩, 사용자와 협의)
- 아래 "무기 구현 방식"을 따른다.

### 5. 정리
- Attack 시트 은퇴, `AimModeTester`·`PlayerController._aimSteps` 같은 임시 하네스 정리.
- `ARCHITECTURE.md`(리그 구조), `OPEN_QUESTIONS.md` #7·#8, `HANDOFF.md` 갱신.

## 무기 구현 방식 (결정 6)

**무기를 하나씩 구현하고, 무기마다 사용자와 먼저 이야기한다.** 모델이 무기 동작을 미리 정해 두지 않는다.

무기 하나를 시작할 때 모델은 아래를 **제안으로** 정리해 대화에서 묻고, 사용자가 정한 것만 구현·기록한다.

1. 동작 종류 — 기존 종류를 쓸지, 새 종류가 필요한지 (예: 베기 / 찌르기 / 내려찍기 / 펼치기 / 걸어 당기기)
2. 팔 동작 — 예비동작에서 팔이 어디로 가고, 타격 때 어떻게 움직이며, 한 손인지 양손인지
3. 무기 그림 — 크기, 손잡이 위치, 쥐는 방향
4. 속도·범위 — `WEAPON_ROSTER.md`의 1차 값(예비·타격·회수, 전방·폭, 호)을 그대로 쓸지 바꿀지
5. 확인 방법 — `WeaponTestArena`에서 무엇을 보면 되는지

정해진 내용은 `WEAPON_ROSTER.md`의 해당 무기 항목에 적는다.

> **참고용 묶음 (모델 제안, 결정 아님):** `WEAPON_ROSTER.md`의 "기본 모션 방향" 칸을 보고 묶으면
> 베기 = AXE·PIPE·WIRE·SPADE·CANE / 찌르기 = PIKE·PEN·EPEE·NEEDLE·SKEWER / 내려찍기 = MACE·STONE·PESTLE / 펼치기 = NET.
> 무기별 대화의 출발점으로만 쓴다. CANE("갈고리 휘두르기")처럼 따로 빠질 수 있는 무기가 있다.

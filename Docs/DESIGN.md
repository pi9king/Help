# Game Design Document

> 2D 플랫포머 로그라이크 + 퍼즐 게임

## 장르 및 핵심 컨셉

- **장르**: 2D 사이드뷰 플랫포머 + 로그라이크 + 퍼즐
- **시점**: 사이드뷰 + 중력 (플랫폼, 바닥, 벽 기반 방 구조)
- **레퍼런스**: Binding of Isaac (방 그리드 구조), Dead Cells/Spelunky (사이드뷰 플랫포머 로그라이크)
- **런 길이**: 1시간 이상 (대형 볼륨)
- **핵심 루프**: 던전 진입 → 방 탐색/전투/퍼즐 → 알파벳 재료 루팅 → 조합/장착 → 다음 방 → 보스 → 층 클리어

## 핵심 테마: 알파벳 "E"

### 컨셉

- **플레이어 캐릭터 = 알파벳 E**
- 던전에서 **다른 알파벳 글자를 재료로 획득**
- 획득한 알파벳과 **E(자기 자신)를 조합**하여 아이템(무기, 장비, 소모품)을 제작
- **E가 포함된 영단어만 아이템으로 존재** — 이것이 게임의 핵심 제약이자 정체성

### 속성 시스템

사용 가능한 속성은 **영단어에 E가 포함된 것만** 허용된다. 약 **15개** 목표.

#### 속성의 역할: 상성이 아닌 "열쇠-자물쇠"

속성은 전투 상성 시스템이 **아니다**. 속성은 **열쇠(key)** 역할을 한다:
- 적/퍼즐에 "속성 잠금"이 걸려 있으면, 해당 속성 무기로만 효과적으로 대응 가능
- 속성 간 우열 관계(가위바위보)는 없음
- 런마다 등장하는 속성 잠금이 다름 → 매 런 다른 경험

#### 데미지 규칙

| 상황 | 데미지 |
|------|--------|
| 일반 적 (속성 잠금 없음) | 모든 무기로 정상 데미지 |
| 속성 잠금 적 + **일치하는 속성 무기** | 정상 데미지 |
| 속성 잠금 적 + **불일치 속성 무기** | 대폭 감소 (클리어 가능하지만 비효율) |

> 완전 면역이 아닌 대폭 감소이므로, 해당 속성 무기 없이도 시간/자원을 투자하면 돌파는 가능하다. 단, 진입 조건 판정에서는 "효율적 클리어 가능 여부"를 기준으로 판단한다.

### 다음 논의: 퍼즐 상호작용 깊이

속성이 15개일 때 퍼즐 기믹 설계 방향:
- **A) 15개 전부 고유 상호작용**: 속성마다 전용 퍼즐 기믹 → 다양성 최대, 제작량 많음
- **B) 그룹화**: 비슷한 속성끼리 퍼즐 기믹 공유 (예: Fire/Flare → "열 기믹") → 기믹 6~7종, 속성 15개
- **C) 퍼즐 전용 속성 제한**: 15개 중 8~10개만 퍼즐 사용, 나머지는 전투 전용
- 미결 상태

### 크래프팅과 알파벳

- 재료 = 알파벳 글자 (A, B, C, D, F, G, ... Z)
- 조합 = E(플레이어) + 알파벳 재료 → 영단어 아이템
- 예시: E + S + W + O + R + D → "SWORD"? (E 미포함이므로 불가)
- 예시: E + B + L + A + D → "BLADE" ✓ (E 포함)
- 예시: E + S + P + A + R → "SPEAR" ✓ (E 포함)
- 예시: E + H + A + M + R → "HAMMER" ✓ (E 포함)

> 구체적인 아이템 목록, 레시피 구조는 별도 논의 필요.

## 퍼즐 시스템 (3가지 유형 병행)

### A. 환경 퍼즐
방 안의 기믹을 풀어야 진행 (스위치, 블록 밀기, 타이밍 점프, 플랫폼 순서 등)

### B. 전투 퍼즐
적을 특정 순서/방법으로 처치해야 클리어 (약점 시스템, 속성 매칭, 환경 활용 등)

### C. 독립 퍼즐 방
전투 없이 순수 퍼즐만 있는 방이 별도 존재 (보상 연결)

## 아이템 / 인벤토리 시스템

### 인벤토리
- 아이템 보관, 정렬, 관리

### 재료 루팅
- 적 처치, 환경 파괴, 퍼즐 클리어 등에서 재료 획득

### 조합 (Crafting)
- 재료를 조합하여 장비/소모품 제작

### 장착 (Equipment)
- 제작한 장비를 장착하여 능력치/스킬 변경

### 분해 (Disassembly)
- 불필요한 아이템을 분해하여 재료로 환원

## 방 진입 판정 시스템 (핵심 메커니즘)

방 진입 가능 여부는 **플레이어가 해당 방의 클리어 조건을 충족하는 아이템을 제작할 수 있는가**로 판정한다.

### 판정에 사용되는 자원 풀

플레이어의 "잠재적 자원"을 계산한다:
1. **인벤토리 내 재료** (현재 보유)
2. **장착 중인 장비를 분해했을 때 나오는 재료** (잠재적)
3. **인벤토리 내 장비를 분해했을 때 나오는 재료** (잠재적)
4. 위 1+2+3을 합산한 총 재료 풀

### 판정 로직

```
CanEnterRoom(room, player):
  requirements = room.GetRequirements()     // 예: 물 속성 무기
  availableMaterials = player.GetTotalMaterialPool()  // 보유 + 분해 가능 재료
  for each req in requirements:
    if not CanCraftAny(req, availableMaterials):
      return false
  return true
```

### 방 유형별 진입 조건

| 방 유형 | 진입 조건 | 예시 |
|---------|----------|------|
| 일반 전투 | 없음 (자유 입장) | 일반 적만 있는 방 |
| 속성 전투 | 특정 속성 무기 제작 가능 | "물 속성 무기 필요" → 물 원석 + 검 재료 보유? |
| 환경 퍼즐 | 특정 유형 무기 제작 가능 | "벽 파괴 필요" → 해머류 무기 제작 가능? |
| 전투 퍼즐 | 속성 + 유형 조합 | "불 적을 물로, 바위를 해머로" |
| 독립 퍼즐 | 없음 또는 특정 도구 | 퍼즐 유형에 따라 다름 |
| 보물/상점 | 없음 | 자유 입장 |
| 보스 | 층 내 필수 방 클리어 | 별도 조건 |

> **주의**: 속성 종류, 무기 유형 카테고리는 아직 미결 상태. 위 예시는 방향성만 보여주는 것이며 구체적 속성/무기 체계는 별도 논의 필요.

### 진입 불가 사유 비공개

문에는 **진입 가능/불가능**만 표시한다. 왜 불가능한지(어떤 속성이 부족한지, 어떤 무기가 필요한지)는 플레이어에게 **일절 공개하지 않는다**. 플레이어가 스스로 재료를 모으고 조합을 시도하면서 해답을 찾아야 한다.

### 던전 생성 시 재료 보장 (제약 조건)

층을 절차적으로 생성할 때, 아래 불변식(invariant)을 반드시 만족해야 한다:

> **"자유 입장 가능한 방들에서 획득 가능한 재료만으로, 해당 층의 모든 조건부 방을 클리어할 수 있어야 한다."**

생성 절차:
1. 방 배치 및 유형 결정
2. 조건부 방의 진입 요구사항 합산
3. 자유 입장 방(일반 전투, 보물, 상점 등)의 루트 테이블에 필요한 재료 배치
4. 검증: 최악의 경우에도 모든 방 클리어 가능한지 확인
5. 실패 시 재료 재배치 또는 방 재생성

# 재미 검증 체크리스트

> **문서 지위:** 이 문서는 확정 사양이 아니라, 현재 구현에서 발견한 **재미 가설과 검증 작업**을 정리한 체크리스트다.
> 체크되지 않은 항목을 게임의 규칙으로 간주하지 않는다. 실험 결과 채택된 결정만 `DESIGN.md`의 결정 로그로 옮긴다.
>
> **핵심 질문:** 플레이어는 필요한 열쇠를 메뉴에서 만드는가, 아니면 단어를 이용해 자기만의 해법을 만드는가?

## 판정 원칙

- [ ] 기능의 존재가 아니라 플레이 중 만들어지는 선택과 감정을 평가한다.
- [ ] 콘텐츠 수를 늘리기 전에 작은 구간에서 코어 재미를 증명한다.
- [ ] 한 번의 플레이에서 관찰 가능한 성공 기준을 정한 뒤 구현한다.
- [ ] 개발자가 의도한 사용법과 플레이어가 실제로 한 행동을 구분해 기록한다.
- [ ] 실패한 실험도 결과와 이유를 남기고, 자동으로 정식 사양으로 승격하지 않는다.

---

## P0 — 코어 재미 증명

### 1. 단어를 서로 다른 ‘동사’로 만들기

목표: 아이템 이름이나 공격력 수치가 아니라, 만든 단어에 따라 조작과 전술이 달라져야 한다.

- [ ] 검증용 단어 3개를 선정한다. 1차 후보는 `AXE`, `ROPE`, `FLARE`다.
- [ ] 각 단어에 전투 용도, 이동/지형 용도, 위험 또는 비용을 하나 이상 정의한다.
- [ ] 세 단어의 공격 범위·속도·위치 변화·대상 반응 중 최소 두 가지가 명확히 다르게 느껴지도록 프로토타입한다.
- [ ] 무기 카테고리가 실제 공격 모션과 판정에 연결되는지 확인한다.
- [ ] `AttackSpeedMult` 같은 데이터가 실제 플레이 차이로 이어지는지 확인하고, 사용하지 않을 값은 선택 판단 근거에서 제외한다.
- [ ] 속성은 단순 면역 해제용 열쇠가 아니라 행동 또는 상황 변화를 만드는지 검증한다.

**통과 기준**

- [ ] 플레이어가 이름이나 공격력 표시를 보지 않고도 세 단어를 행동만으로 구분한다.
- [ ] 같은 방을 다시 플레이할 때 다른 단어를 선택하면 접근 방식이 달라진다.
- [ ] 플레이어가 “가장 숫자가 큰 무기” 외의 이유로 단어를 선택한다.

### 2. 자물쇠가 아닌 퍼즐 만들기

목표: 정답 아이템 보유 여부가 아니라 관찰, 선택, 순서, 공간 활용을 요구한다.

- [ ] 하나의 문제를 최소 두 가지 단어로 해결할 수 있는 테스트 방을 만든다.
- [ ] 아무 단어도 쓰지 않는 고위험 해법을 하나 제공한다.
- [ ] 해법마다 보상, 체력 위험, 시간, 글자 소비 중 하나 이상의 차이를 둔다.
- [ ] 사용해야 할 아이템 이름을 직접 표시하지 않고도 환경에서 해법을 추론할 단서를 제공한다.
- [ ] `EnvironmentPuzzle`, `CombatPuzzle`, `PurePuzzle`이 실제 플레이에서 무엇이 다른지 각각 한 문장으로 설명할 수 있게 만든다.
- [ ] 세 퍼즐 타입이 같은 콘텐츠 프리팹을 공유하는 현재 구조가 검증에 방해된다면 분리한다.

**통과 기준**

- [ ] 첫 시도에서 모든 플레이어가 같은 행동을 하지 않는다.
- [ ] 실패한 플레이어가 무작위 아이템 사용이 아니라 환경 단서를 근거로 다음 시도를 설명한다.
- [ ] 정답을 안 뒤에도 실행 과정에 판단이나 숙련이 남는다.

### 3. 지형과 전투를 하나의 인카운터로 설계하기

목표: 방 모양이 배경에 머물지 않고 적의 위협과 플레이어의 단어 선택을 바꿔야 한다.

- [ ] 템플릿 마커와 콘텐츠 배치의 연결 여부를 확인하고, 검증 방에서는 적·장애물·보상을 지형과 함께 배치한다.
- [ ] 진입 방향이 바뀌면 같은 적 조합도 다른 판단을 요구하도록 만든다.
- [ ] 고지대 궁수, 좁은 길목의 브루트처럼 지형의 의미를 설명할 수 있는 적 배치를 만든다.
- [ ] 적이 다층 지형에서 플레이어를 추적하거나 압박할 방법을 제공한다.
- [ ] 플레이어가 높은 발판에 올라가는 것만으로 전투를 무력화할 수 있는지 확인한다.
- [ ] 반복되는 중앙 발판 사다리와 4방향 문 구조를 벗어난 방을 최소 하나 시험한다.

**통과 기준**

- [ ] 플레이어가 적 종류뿐 아니라 지형을 보고 장비나 진입 경로를 바꾼다.
- [ ] 안전지대에서 같은 공격만 반복하는 것이 최적 전략이 아니다.
- [ ] 테스트 후 플레이어가 방 하나를 고유한 상황으로 기억한다.

### 4. 보스를 단어 시스템의 시험으로 만들기

목표: 체력이 많은 일반 적이 아니라, 한 층에서 배운 단어 활용을 종합하는 전투를 만든다.

- [ ] 보스가 최소 세 가지 구분 가능한 패턴을 사용하게 한다.
- [ ] 패턴 중 하나 이상이 지형 또는 단어 능력과 상호작용하게 한다.
- [ ] 서로 다른 단어가 각각 유효하지만 다른 위험을 만드는 대응법을 설계한다.
- [ ] 피해를 줄 수 없는 대기 시간과 단순 체력 소모 구간을 측정한다.
- [ ] 보스 보상이 숫자 상승뿐 아니라 다음 층의 플레이 방식을 바꾸는지 검증한다.

**통과 기준**

- [ ] 첫 패배 후 플레이어가 “공격력이 부족했다” 외의 학습 내용을 설명한다.
- [ ] 숙련된 플레이어의 승리 시간이 단순 장비 공격력보다 패턴 이해에 더 크게 영향받는다.
- [ ] 서로 다른 단어 구성으로 승리한 플레이 기록이 나온다.

### 5. 제작과 사용 사이의 마찰 줄이기

목표: 단어를 떠올린 순간부터 실제 행동까지 흐름이 끊기지 않아야 한다.

- [ ] `획득 → 제작 UI → 제작 → 인벤토리 UI → 장착 → 사용`에 필요한 입력 수와 시간을 측정한다.
- [ ] 제작 직후 장착, 빠른 교체, 상황 기반 단축 조작 중 하나 이상을 프로토타입한다.
- [ ] 잠긴 문이나 장애물이 요구 아이템을 숨기더라도 추론 가능한 시각·음향 단서를 제공한다.
- [ ] 메뉴를 열고 레시피 목록을 훑는 행동이 퍼즐 풀이를 대체하는지 관찰한다.
- [ ] 전투 도중 단어 전환이 의도된 재미인지, 전투 전 준비가 의도된 재미인지 결정할 근거를 수집한다.

**통과 기준**

- [ ] 숙련된 플레이어가 일반적인 제작·장착을 3초 안에 완료한다.
- [ ] 테스트 참가자가 조작 순서를 묻지 않고 첫 단어를 사용할 수 있다.
- [ ] 플레이 시간 중 메뉴 체류 비율이 의도한 템포를 해치지 않는다.

## P1 — 반복 플레이의 의미 만들기

### 6. 절차 생성이 선택을 바꾸는지 검증하기

- [ ] 방 연결 모양이 아니라 실제 상황과 선택이 달라지는 변수를 목록화한다.
- [ ] 동일 좌표가 반복적으로 같은 템플릿을 고르는 현재 시드 방식의 체감 영향을 확인한다.
- [ ] 층별 콘텐츠 폴백 때문에 2·3층이 1층의 반복으로 느껴지는지 플레이 기록으로 확인한다.
- [ ] 룸 타입마다 콘텐츠 후보가 하나뿐인 상태에서 생성되는 반복 패턴을 기록한다.
- [ ] 방 수를 늘리기 전에 `지형 × 적 조합 × 진입 방향 × 보상` 조합 중 효과가 큰 축을 찾는다.

**통과 기준**

- [ ] 두 번의 플레이에서 플레이어가 서로 다른 중요한 결정을 하나 이상 회상한다.
- [ ] 지도 모양을 가린 플레이 기록만 보더라도 두 런의 전투·퍼즐 전개를 구분할 수 있다.

### 7. 글자 예산에 진짜 기회비용 만들기

- [ ] 제작 가능성을 보장하는 현재 층 예산이 선택을 지나치게 예정하는지 확인한다.
- [ ] 하나의 글자가 둘 이상의 매력적인 단어에 경쟁적으로 사용되게 한다.
- [ ] 필수 진행 능력에 사용할 글자와 선택적 강화를 위한 글자 사이에 고민을 만든다.
- [ ] 정답 단어가 없어도 우회, 체력 지불, 상점, 분해 등으로 런을 이어갈 수 있는 복구 수단을 시험한다.
- [ ] 적별 글자 보상이 비어 있거나 편중될 때 전투 보상이 무의미하게 느껴지는지 확인한다.

**통과 기준**

- [ ] 플레이어가 제작 가능하다는 이유만으로 즉시 만들지 않고 다음 방을 고려해 보류한다.
- [ ] 런 종료 후 “다음에는 다른 글자 사용을 해보겠다”는 계획이 나온다.

### 8. 죽음 뒤에 다시 시작할 이유 확인하기

- [ ] 메타 성장 없이도 지식, 숙련, 새로운 조합 시도가 재도전 동기가 되는지 확인한다.
- [ ] 죽기 직전의 결정 중 플레이어가 자신의 실수라고 받아들이는 것을 기록한다.
- [ ] 반복 구간을 다시 통과하는 시간이 새로운 선택을 만나기까지 너무 긴지 측정한다.
- [ ] 영구 성장 도입 여부는 코어 루프가 재미있다는 증거를 얻은 뒤 판단한다.

## P2 — 게임의 고유한 인상 강화

### 9. 주인공 `E`와 단어 변화를 시각적으로 연결하기

- [ ] 기사·도적 장식 없이도 플레이어가 주인공을 `E`로 인식하는지 확인한다.
- [ ] 제작한 단어가 캐릭터의 실루엣, 공격, 이동, 이펙트 중 하나를 변화시키게 한다.
- [ ] 글자가 결합·분해·소비되는 과정을 게임 세계 안에서 보여주는 연출을 시험한다.
- [ ] 일반적인 판타지 캐릭터와 구분되는 스크린샷 한 장을 만들 수 있는지 확인한다.
- [ ] 시각 효과가 현재 보유 단어와 가능한 행동을 설명하는 UI 역할도 하는지 검증한다.

**통과 기준**

- [ ] 게임을 처음 본 사람이 스크린샷이나 10초 영상만 보고 “글자와 단어를 사용하는 게임”이라고 추측한다.

### 10. 전투 손맛의 최소 깊이 확보하기

- [ ] 기본 공격 하나만 반복할 때 재미가 유지되는 시간을 측정한다.
- [ ] 공격의 선딜, 유효 시간, 후딜과 플레이어 입력 잠금이 의도한 리듬을 만드는지 체감 테스트한다.
- [ ] 점프 공격, 방향 공격, 차지, 패링, 콤보 중 어떤 하나가 단어 시스템과 가장 잘 결합하는지 작은 실험으로 비교한다.
- [ ] 대시가 단순 회피를 넘어 특정 단어 또는 적 패턴과 상호작용할 여지가 있는지 시험한다.
- [ ] 히트스톱, 카메라 반응, 넉백이 무기별 무게 차이를 전달하는지 확인한다.

## 플레이테스트 기록 양식

각 실험은 아래 항목을 짧게 기록한다.

- 빌드/커밋:
- 실험한 가설:
- 참가자와 플레이 시간:
- 선택한 단어와 선택 이유:
- 가장 영리하다고 느낀 순간:
- 가장 반복적이거나 귀찮았던 순간:
- 메뉴에서 막힌 횟수:
- 안전지대 또는 단일 전략으로 무력화한 상황:
- 죽음/성공 뒤 다시 해보고 싶다고 말한 선택:
- 관찰 결과: 채택 / 수정 후 재시험 / 폐기
- `DESIGN.md`로 옮길 결정:

## 1차 마일스톤 완료 조건

다음을 모두 만족할 때 코어 재미가 최소한 증명된 것으로 본다.

- [ ] 세 단어가 명확히 다른 조작과 전술을 제공한다.
- [ ] 하나의 상황에 복수 해법과 의미 있는 비용 차이가 존재한다.
- [ ] 지형과 적 배치가 단어 선택에 영향을 준다.
- [ ] 보스가 단어 시스템의 이해를 시험한다.
- [ ] 제작·장착 과정이 플레이 흐름을 과도하게 끊지 않는다.
- [ ] 외부 플레이테스트 참가자 3명 이상에게서 서로 다른 선택 사례가 나온다.
- [ ] 참가자 다수가 다음 런에서 시험하고 싶은 다른 조합을 자발적으로 언급한다.
